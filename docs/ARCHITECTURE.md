# Architecture and governance

Each admitted query gets an isolated DataFusion session, a cancellation token, a deadline and a lease on the global concurrency semaphore. Sessions share a bounded FairSpillPool, but have separate object-store registries. Query streams retain their lease until completion, error or drop. The default runtime has one inbound interface: REST. The Docker image includes `postgres-wire` for Cube compatibility; its listener is inactive unless `pg_addr` is configured. Native Cargo builds keep this compile-time feature optional. Dropping an HTTP/optional PG stream cancels the query and releases its resources. PostgreSQL drivers receive a cancel request; warehouse jobs with known handles receive vendor cancel requests. Delivery of remote cancellation cannot be guaranteed during network failure.

The federation optimizer partitions the logical plan by source and authorization context. SQL-capable fragments (including projection, predicates, aggregates, compatible joins and limits) are translated to the source dialect and executed there. Different sources have different compute-context identifiers. PostgreSQL EXPLAIN supplies estimated row counts and widths; optional estimates are isolated by savepoints. DataFusion uses source statistics and Parquet footer statistics for local join planning. This is not a network/egress-price optimizer; dynamic runtime filter shipping and adaptive remote semijoins are not implemented.

Parquet file manifests contain exact objects and ETags. The read-only object-store wrapper allows only manifest objects, sends If-Match for reads/HEAD requests, and rejects writes. This protects against changed file content; an ETag change aborts rather than mixing versions. Metadata and data are read with ranged requests. DataFusion performs projection and row-group/page pruning; the metrics wrapper transparently propagates physical predicates. `limits.parquet_row_filter_pushdown` additionally enables row-level late materialization. It defaults to false because filtering one column before fetching other columns can multiply remote requests when most row groups still match; enable it when avoided decoding/bytes outweigh those requests. This switch does not disable row-group pruning. No prefix is silently treated as an Iceberg table.

Iceberg uses the official Rust implementation and IcebergStaticTableProvider. Glue GetTable and S3 FileIO use the same resolved AWS credentials, frozen for the query; a second provider chain cannot select a different role. Expired temporary credentials fail rather than changing identity mid-query. The returned metadata pointer is frozen for that query and must be under the configured warehouse. The `IsRegisteredWithLakeFormation` flag causes rejection. No metadata refresh occurs during a query. Explicit snapshot IDs use that snapshot's schema. Old snapshots must remain physically available; concurrent snapshot expiration can cause a read failure.

PostgreSQL checks out one connection per referenced source and query from a bounded source pool. BEGIN REPEATABLE READ READ ONLY establishes a fresh source transaction; scans use that transaction and run serially on the connection. Successful completion rolls back and resets the backend before reuse; failures, cancellation and abandoned streams discard it. The engine sets UTC, ISO dates and a statement timeout. Superuser, BYPASSRLS and NOLOGIN roles are refused on every checkout. Table/view grants and RLS remain in PostgreSQL. See [pool and cache contracts](PERFORMANCE.md). No raw backing-file reads are used for Databricks, Snowflake or BigQuery; permissions and policies are evaluated by their SQL service. Warehouse table versions/timestamps are mandatory, and the rewriter applies the pin to every occurrence of the table.

ClickHouse uses the configured SQL identity over HTTPS and consumes uncompressed ArrowStream batches. The decoder validates frame sizes before allocation, rejects compressed/dictionary messages, and requires both the IPC end marker and clean HTTP EOF. It does not retain the result set. Source settings constrain execution memory, threads and deadline, and source row policies remain authoritative. Each query permits at most one statement per configured ClickHouse source; another statement fails because no shared repeatable-read snapshot exists. See [ClickHouse semantics and profile](CLICKHOUSE.md).

A deployment uses configured service principals. REST/PG authentication does not impersonate the end user at each source. Deploy separate instances/configurations for different trust domains until end-user identity propagation exists. An authenticated client can query every table granted to the configured source principal and registered in the configuration. Diagnostics may contain SQL literals and object names, so they require the same access boundary.

There is no globally atomic snapshot across independent systems. The guarantee is a PostgreSQL source transaction, an immutable Parquet manifest, an Iceberg snapshot, explicit warehouse time travel, or ClickHouse native statement-level reads. The clocks and commit points across those systems are independent.

The DataFusion memory pool limits tracked query-operator allocations, not the process RSS. Remote pages and Arrow conversion buffers are separately capped; some readers, metadata and delete indexes allocate outside the pool. Docker/cgroup limits enforce a hard process boundary. Sort/join/aggregate operators spill where DataFusion supports it; others fail on exhaustion. Spill quotas are per query; aggregate disk demand is bounded by concurrency times the configured quota. Keep spill storage private and encrypted according to the deployment's data requirements.

Metrics distinguish measured source payload bytes from Arrow batch sizes. PostgreSQL byte counts sum decoded text value lengths (not TCP bytes); S3 counts returned body bytes; warehouse HTTP counts decoded JSON body bytes; ClickHouse counts received IPC body bytes. Iceberg's separate FileIO does not yet expose read bytes here: the field is null, not a fabricated zero. Per-source elapsed time is summed operation/stream lifetime and can include downstream backpressure; parallel source times need not add to wall time. Final physical plans include DataFusion operator metrics, including spills where reported.
